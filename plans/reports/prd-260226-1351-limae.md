# PRD: EbookPolish

**Status:** Draft | **Date:** 2026-02-26 | **Version:** 0.1

---

## 1. Problem Statement

Self-published authors finish writing in Word / Google Docs / Scrivener, export to EPUB or PDF, and then face a painful final-mile QA step: grammar errors slip through, images are absent or misplaced, and TOC/navigation is often broken or missing — causing KDP rejections or poor reader experience. Hiring a proofreader costs $200–500; hiring an illustrator costs $50–200 per image. Most authors skip both.

**Core pain:** The gap between "finished draft" and "ready to publish" is expensive and tedious when done manually.

---

## 2. Target User

**Primary:** Indie / self-published authors uploading to KDP, Gumroad, Leanpub, or Smashwords

**Secondary:** Content marketers and course creators publishing lead-gen or paid ebooks

**Persona:**
- Writes 2–6 ebooks/year
- Works alone — no editor, no designer
- Already has a finished or near-finished EPUB/PDF
- Willing to pay $10–30 per ebook processed, or $20–40/month for a subscription
- Non-native English speakers are a significant subsegment (ESL authors on KDP)

---

## 3. Goals & Success Metrics

| Goal | Metric | Target |
|------|--------|--------|
| Authors successfully process ebooks end-to-end | Completion rate (upload → download) | ≥ 80% of initiated sessions |
| Grammar fix delivers value | User-rated quality score after download | ≥ 4/5 average |
| EPUB structure preserved post-processing | Zero formatting corruption reports | < 2% error rate |
| Monetization | Paid conversions from free trial | ≥ 15% within 7 days |
| Retention | Monthly active authors on subscription | ≥ 60% month-2 retention |

---

## 4. Scope

### Must Have (MVP)

- **Upload:** Accept EPUB and PDF files (max 50MB)
- **Grammar Fix:** AI-powered grammar, punctuation, and spelling correction across full manuscript; preserve original EPUB structure and formatting
- **Nav/TOC Repair:** Parse EPUB structure → detect missing/broken TOC → auto-generate or repair NCX / nav.xhtml
- **Download:** Output corrected EPUB (and optionally PDF)
- **Audit Report:** Before download, show a summary: # of grammar fixes, TOC issues resolved, image gaps detected
- **Modular selection:** Author checks which fixes to apply before processing starts
- **Pay-per-use:** Single ebook processing payment (no account required for first use)

### Should Have (v1.1)

- **Image Generation:** Detect chapters lacking visuals → suggest AI-generated images → author approves/rejects → embed into EPUB
- **Subscription tier:** Monthly plan for authors processing 3+ ebooks/month
- **Batch processing:** Upload multiple ebooks at once

### Won't Have (MVP)

- Full ebook editor / writing environment
- Real-time collaborative editing
- Cover design / full cover generation
- Distribution / direct publishing to KDP (out of scope — we enhance, not publish)
- Plagiarism detection
- Translation

## 5. User Stories

### Story 1 — Grammar Fix
> As a non-native English author, I want to upload my EPUB and get grammar errors corrected automatically so that I don't have to pay a human proofreader before publishing.

**Acceptance Criteria:**
- Given an uploaded EPUB, when grammar fix is selected and processing completes, then the downloaded EPUB contains corrected text with ≥ 90% of flagged grammar errors addressed
- Given a corrected EPUB, when I open it in a reader, then chapter structure, fonts, and formatting are identical to the original
- Given processing, when it completes, then an audit report lists how many sentences were modified

### Story 2 — TOC / Nav Repair
> As an author whose KDP upload was rejected for navigation errors, I want the tool to repair my EPUB's TOC so that my book passes validation on the first re-submission.

**Acceptance Criteria:**
- Given an EPUB with missing or malformed nav.xhtml/NCX, when nav repair is selected, then the output passes EPUBCheck validation
- Given a repaired EPUB, when opened in iBooks or Kindle Previewer, then chapters are navigable via the built-in TOC
- Given a valid TOC already exists, when repair is selected, then the tool does not alter it

### Story 3 — Modular Selection
> As an author who only needs grammar fixed (not images), I want to pick exactly which enhancements to apply so that I only pay for what I need.

**Acceptance Criteria:**
- Given the processing screen, when I deselect "Image Generation", then no image API calls are made and pricing reflects grammar-only
- Given selected options, when I confirm, then a price estimate is shown before payment

### Story 4 — Audit Report
> As an author, I want to see a report of what was changed before I download so that I can decide whether to accept the changes.

**Acceptance Criteria:**
- Given completed processing, when the report is shown, then it lists: grammar fixes count, TOC issues resolved, image gaps detected
- Given the report, when I click "Review Changes", then I can see a diff of grammar changes before downloading
- Given I reject changes, when I choose "Download Original", then my original file is returned unchanged

### Story 5 — Pay-per-use
> As a first-time user, I want to process one ebook without creating an account so that I can evaluate the product before committing.

**Acceptance Criteria:**
- Given landing on the site, when I upload an ebook, then I can complete processing and pay without registering
- Given payment completed, then a download link is emailed and shown on-screen
- Given 24 hours, then the download link expires for privacy

---

## 6. Non-Goals

- We do not write or generate book content from scratch
- We do not store ebook content after 24 hours of processing (privacy)
- We do not offer an in-browser reading or editing experience
- We do not support MOBI or AZW3 formats in MVP (EPUB and PDF only)

---

## 7. Constraints

- **Privacy:** Ebook content must not be stored beyond 24h; no training on user data
- **EPUB integrity:** Processing must never corrupt EPUB structure — EPUBCheck validation required on output
- **File size:** MVP limit 50MB per file
- **API dependency:** Grammar fix depends on third-party LLM API (Claude or OpenAI); image gen depends on image API (Imagen / DALL-E / Flux) — both must have fallback/graceful degradation
- **Legal:** AI-generated images must be flagged as AI-generated in metadata; copyright responsibility lies with user

## 9. Technical Notes (Non-prescriptive)

- EPUB is a ZIP archive — processing pipeline: unzip → parse OPF/HTML → transform → repack → validate
- Grammar fix should process chapter-by-chapter to handle context window limits
- Nav repair must handle both EPUB2 (NCX) and EPUB3 (nav.xhtml) formats
- Processing should be async with a job queue — large books may take 1–3 minutes
